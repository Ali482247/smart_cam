# План доработки Three Cam

## Цель

Сделать приложение стабильным для записи с нескольких телефонов:

- экран телефона не должен отключаться, пока приложение открыто, особенно во время записи;
- в мобильном приложении должны появиться настройки;
- настройки должны сохраняться локально на телефоне;
- каждый телефон должен иметь постоянную роль: например `1 устройство`, `2 устройство`, `3 устройство`;
- контроллер не должен случайно менять порядок устройств после авто-поиска;
- видеофайлы должны называться и сохраняться предсказуемо;
- должны быть доступны настройки сетки, разрешения, FPS и других важных параметров записи.

## Текущее состояние

- Мобильное приложение находится в `three_cam_mobile/lib/main.dart`.
- Android-нативный код находится в `three_cam_mobile/android/app/src/main/kotlin/com/example/three_cam_mobile/MainActivity.kt`.
- Python-контроллер находится в `three_cam_controller.py`.
- Сейчас камера запускается с `ResolutionPreset.veryHigh`, а в `/status` жёстко отдаются `1920x1080`, `30fps`.
- Авто-поиск телефонов сортирует найденные URL и назначает им имена `one`, `two`, `three`, из-за этого роли устройств могут меняться.
- Настроек в мобильном приложении пока нет.
- Для локального сохранения настроек понадобится добавить Flutter-зависимость `shared_preferences`.

## Этап 1. Экран не отключается

1. Добавить нативный Android-метод через существующий `MethodChannel('three_cam/media')`.
2. Включать `WindowManager.LayoutParams.FLAG_KEEP_SCREEN_ON`, когда Flutter-экран камеры создан.
3. Держать экран включённым всё время, пока приложение открыто.
4. На `dispose` или при закрытии Activity очищать флаг.
5. Дополнительно отобразить в `/status`, включён ли режим `keepScreenOn`.

Ожидаемый результат: телефон не засыпает при открытом приложении и во время записи.

## Этап 2. Локальные настройки мобильного приложения

1. Добавить модель настроек в Flutter:
   - `deviceLabel`: имя/номер устройства, например `one`, `two`, `three` или `device_1`;
   - `deviceSlot`: номер устройства `1`, `2`, `3` и так далее;
   - `gridMode`: режим сетки, например `off`, `3x4`, `4x3`;
   - `resolutionPreset`: `low`, `medium`, `high`, `veryHigh`, `ultraHigh`, `max`;
   - `fps`: целевой FPS, например `24`, `30`, `60`;
   - `enableAudio`: включать ли звук;
   - `keepScreenOn`: держать экран включённым;
   - `saveToGallery`: сохранять копию в `DCIM/ThreeCam`;
   - `filePrefix`: дополнительный префикс имени файла, если нужен.
2. Сохранять эти настройки через `shared_preferences`.
3. Загружать настройки при старте до инициализации камеры.
4. При изменении настроек переинициализировать камеру, если меняется разрешение, FPS или звук.
5. Отдавать настройки в `/status`, чтобы контроллер видел реальные параметры телефона.

## Этап 3. UI настроек в приложении

1. Добавить кнопку настроек поверх камеры.
2. Сделать отдельный экран или bottom sheet настроек.
3. Реализовать элементы управления:
   - выбор номера устройства;
   - поле/выбор имени устройства;
   - выбор сетки `off`, `3x4`, `4x3`;
   - выбор разрешения;
   - выбор FPS;
   - переключатели звука, сохранения в галерею и `keep screen on`.
4. Показывать текущий IP, порт, статус записи, свободную память и имя устройства.
5. Сетку отображать поверх превью камеры, если она включена.

## Этап 4. Стабильная идентификация телефонов

1. В мобильном `/status` и discovery-ответе отдавать:
   - нативный `deviceId`;
   - `deviceName`;
   - сохранённый `deviceSlot`;
   - сохранённый `deviceLabel`;
   - текущий IP и порт.
2. В Python-контроллере хранить телефоны по стабильному `deviceId`, а не только по IP.
3. При авто-поиске обновлять IP существующего телефона, но не перезаписывать его роль.
4. Если найден новый телефон, добавлять его как новое устройство с новым слотом.
5. Не переназначать `one/two/three` каждый раз после сортировки по IP.

Ожидаемый результат: если телефон был назначен как `1 устройство`, он останется `1 устройством` даже после перезапуска, смены IP или нового авто-поиска.

## Этап 5. Настройки контроллера

1. Расширить `three_cam_controller_config.json`:
   - хранить `device_id`;
   - хранить `device_slot`;
   - хранить `camera_name`;
   - хранить последний известный IP/URL;
   - хранить целевые параметры записи.
2. В GUI контроллера добавить простой экран/таблицу устройств:
   - найденное имя;
   - device id;
   - URL;
   - слот;
   - camera name;
   - статус.
3. Добавить возможность вручную назначить устройству слот и имя.
4. Сохранять изменения в JSON-конфиг.

## Этап 6. Параметры видео

1. На мобильной стороне применять выбранный `ResolutionPreset`.
2. Проверить поддержку FPS через доступные возможности плагина `camera`.
3. Если прямой выбор FPS недоступен в текущем плагине, сделать честное поведение:
   - хранить желаемый FPS;
   - показывать его в настройках и `/status`;
   - не обещать, что Android реально принудительно пишет именно этот FPS без нативного Camera2-кода.
4. Если понадобится реальное принудительное FPS, отдельным этапом добавить нативную Camera2-реализацию или подобрать подходящий Flutter-плагин.

## Этап 7. Правильное сохранение файлов

1. Использовать стабильный формат имени:
   - `<camera_name>_<YYYYMMDD>_<HHMMSS>_<session_index>.mp4`.
2. Брать `camera_name` из сохранённой роли устройства, а не из случайного порядка discovery.
3. Сохранять локальную копию в директорию приложения.
4. Если включено `saveToGallery`, сохранять копию в `DCIM/ThreeCam`.
5. В `/videos` отдавать имя, размер, дату изменения и session id, если доступен.
6. В Python-загрузке складывать файлы по `camera_name` или `device_slot`, а не по нестабильному hostname.

## Этап 8. Проверка

1. Запустить `flutter analyze`.
2. Запустить существующие Flutter-тесты, если они актуальны.
3. Собрать debug APK.
4. Проверить вручную:
   - экран не выключается при открытом приложении;
   - настройки сохраняются после перезапуска;
   - сетка отображается корректно;
   - запись стартует и останавливается;
   - файлы называются по роли устройства;
   - контроллер не меняет роли телефонов после повторного авто-поиска.

## Что я предлагаю реализовать первым после подтверждения

1. `keep screen on`, потому что это самый критичный баг для записи.
2. `shared_preferences` и базовую модель настроек.
3. Экран настроек в Flutter.
4. Стабильную роль телефона в discovery/status.
5. Обновление Python-контроллера, чтобы он перестал случайно переназначать устройства.
